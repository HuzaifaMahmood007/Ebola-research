# Encoder Results Matrix — single vs joint vs LODO vs LDO

Generated by `results_matrix.py` from the JSON records in `results/{single,joint,lodo}/`. 
Scoring authority is `score.py` (self-check passes; 7 metrics live). No numbers in this 
document are carried over from any earlier write-up — every cell is recomputed from disk.


**Metrics:** rmse, mae, pcc, smape, peak_intensity, peak_timing, nrmse. 
**Aggregation:** `country_macro` — per-node scores averaged within a country, then countries 
averaged with equal weight. For the three influenza bundles this is identical to `node_mean` 
(one country); only dengue's 12 countries make them differ.


**Reporting rules applied:** every cell carries `mean ± sd (n seeds)`; a 1-seed cell says so 
and gets no standard deviation. Nothing is averaged across datasets. Every delta table names 
its reference. Deltas are paired by seed with a t-based 95% interval, and a cell whose 
interval covers zero reads `within noise` instead of a direction.


**Units.** Error-metric deltas are improvement percent (positive = better than reference). 
`pcc` deltas are correlation POINTS, never a percent — a correlation is signed and can sit 
near zero, where a percent change explodes or flips sign on a model that genuinely improved.

## 5. The two fold structures side by side — LODO vs LDO


Client decision D1: *"report both structures as separate tables"*. They measure different things and the distinction is the point of the Week-4 fold fix.


- **LODO — leave-one-DATASET-out.** Hold out flu-Japan and the encoder has still trained on flu-US-regions and flu-US-states. This is **population transfer**: the disease is not held out. 1 seed (42) only.

- **LDO — leave-one-DISEASE-out.** All three influenza bundles held out together as one fold, against dengue as the other. This is **cross-disease transfer**, the number the paper's central claim rests on. 4 seeds on the flu fold, 5 on dengue.

A delta is only meaningful if the two arms scored the same node population. `score.py` drops constant-truth nodes, and a different prediction can change which nodes qualify, so this is checked per (dataset, horizon, seed) against the `single` reference rather than assumed.

## 7. Reading notes and known gaps


**LDO fold directions on disk** (which arm produced each row):


- `LDO adapted` / dengue: flu2dengue

- `LDO adapted` / influenza_japan: dengue2flu

- `LDO adapted` / influenza_us-regions: dengue2flu

- `LDO adapted` / influenza_us-states: dengue2flu

- `LDO zero-shot` / dengue: flu2dengue

- `LDO zero-shot` / influenza_japan: dengue2flu

- `LDO zero-shot` / influenza_us-regions: dengue2flu

- `LDO zero-shot` / influenza_us-states: dengue2flu



- **LODO (leave-one-dataset-out) is 1 seed.** Every LODO cell is seed 42 alone, so it carries no dispersion and no delta against it is testable. It is kept because the client asked for both fold structures side by side, not because it is confirmed.

- **`LODO zero-shot` has no `nrmse`.** Zero-shot runs write JSON only — `train/lodo.py` discards the per-node arrays (`zrecs, _, _, _`, lodo.py:418) — so `rescore_encoder.py`, which globs `*__pernode.npz`, structurally cannot backfill them. The newer `LDO zero-shot` runs are unaffected: they were trained after `nrmse` entered `score.METRICS` and recorded it natively. Recovering `nrmse` for LODO zero-shot needs a rerun, not a rescore.

- **The LDO flu rows are 4 seeds, not 5** (52/62/72/82; seed 42 absent), while LDO dengue has all 5. Paired deltas on the flu rows therefore rest on a 4-seed overlap.

- **`joint:sqrt-uniform` is 1 seed.** It is the sampler-variant probe, not a confirmed arm.

- **`peak_timing` deltas drop cells with a zero-error reference.** A reference that already peaked in exactly the right step gives a 0 denominator, and a percentage against it is undefined rather than infinite. Those seeds are excluded from the pairing, so a peak_timing delta can rest on fewer seeds than the same cell's rmse delta — read the `n` on the cell.

- **UQ metrics are still absent.** WIS, CRPS, empirical coverage, interval width and PIT are implemented and self-checked in `score.py`, but they consume quantile predictions and no run archives them yet. This is the remaining gap against Review Doc ¶7.

- **Baselines are not in this document.** It covers our encoder only, per the request. The published-vs-reproduced baseline comparison is `paper_compare.py`, and HeatGNN was still running when this was generated.
