# Reproducibility

**Emerging Disease Forecasting Framework**

How to obtain the inputs, rebuild the datasets, re-run every experiment, and regenerate every
reported number from a clean machine — and, equally, what cannot be reproduced from this repository
alone and why.

This is the operational companion to three documents that must not be duplicated here:
[data_audit.md](progress/planning/data_audit.md) records what the data *are* and every alteration
made to them; [data_pipeline.md](progress/planning/data_pipeline.md) specifies the build and the
schema contract; [Ebola_Prereg.md](progress/decisions/Ebola_Prereg.md) is the frozen protocol for the
case study. Where a justification is needed here, this document states the conclusion and points to
the evidence.

## 1. The three layers, and what ships in each

Reproduction is layered, and each layer is regenerable from the one above it. Knowing which layer you
are trying to reproduce decides how much work it is.

| Layer | Contents | In the repository? | Cost to regenerate |
|---|---|---|---|
| **L1 — raw sources** | 12 source files (~559 MB) + 16 GADM shapefiles (~486 MB) | No. DVC pointers only; every file is publicly downloadable and checksum-pinned | Download time |
| **L2 — datasets** | `data/processed/*.npz` — 6 built bundles + 2 frozen Ebola arms, plus `config.json` and two environment records (16 MB) | **Yes, committed** | ~10 min, CPU |
| **L3 — results** | `results/**` — 1,248 artifacts, 3.7 GB: 449 JSON record files (one record per `model × dataset × horizon × seed × metric`) plus the per-node, per-origin, quantile and checkpoint archives | No, gitignored | Tens of GPU-hours (§7) |
| **L4 — tables and figures** | Markdown/`.docx` reports under `Reports/` and `progress/outcomes/` | Partly; `Reports/` is gitignored | Seconds to minutes, from L3 |

**The datasets are committed deliberately.** They are the artifact every claim in the paper depends
on, they are small enough to version (16 MB total), and shipping them means a reader can check every
result without first reconstructing a 1 GB download. The raw sources sit behind DVC (Azure remote,
private) because their licence terms and size make redistribution the wrong call — but §12 gives the
public URL and the pinned checksum for each, so a third party can reconstruct L1 independently and
confirm they hold the same bytes.

**No reported number is typed by hand.** Every table in every report is generated by a reader script
from the L3 records (§8). This is the property that makes the paper's numbers auditable: a claim in
prose can be traced to a JSON record, and that record to the command that wrote it.

## 2. Environments

Two conda environments, deliberately separate: the geometry stack (GEOS/GDAL/PROJ via geopandas) and
the training stack (CUDA torch) do not co-resolve, and forcing them into one environment produces a
solve that satisfies neither.

| Env | Python | Key contents | Runs |
|---|---|---|---|
| `ebola` | 3.10 | numpy 2.2, pandas 2.3, geopandas 1.1, libpysal 4.13, shapely 2.1, openpyxl 3.1 | the data build, the leakage suite, anything touching geometry |
| `ebola-train` | 3.11 | torch 2.6.0+cu124, numpy 2.4.6, scipy 1.17.1, pandas 3.0.3 | all training, scoring, and analysis |

```bash
# build / data environment — pinned in environment.yml
conda env create -f environment.yml

# training environment — pinned in data/processed/env_train.txt
conda create -n ebola-train python=3.11 numpy scipy pandas -c conda-forge
conda run -n ebola-train pip install torch --index-url https://download.pytorch.org/whl/cu124
```

The exact resolved package sets these results were produced under are committed as
[data/processed/env.txt](data/processed/env.txt) and
[data/processed/env_train.txt](data/processed/env_train.txt), both written by `pip freeze` at build
time.

**Two environment traps, both of which have cost real time on this project:**

- **OpenMP collision on Windows.** `torch` ships `libomp.dll` and pandas' MKL ships `libiomp5md.dll`;
  both initialise OpenMP in one process and the second one aborts. Every training entry point sets
  `KMP_DUPLICATE_LIB_OK=TRUE` *before* importing numpy, torch or pandas. If you add a new entry
  point, copy that line — it must run before the imports, not after.
- **Call the interpreter by absolute path for long jobs.** This machine has both an anaconda3 and a
  miniconda3 install, so a bare `python` after `conda activate ebola-train` can still resolve to the
  interpreter without torch. `run_overnight.py` preflights for CUDA and exits immediately rather than
  failing six hours in; when launching a multi-hour job by hand, use
  `"C:\Users\<user>\miniconda3\envs\ebola-train\python.exe" -u <script>`.

## 3. Hardware

Everything reported was produced on a **single NVIDIA RTX 3060, 12 GB**, under Windows 11.

The 12 GB is adequate for every job here **provided the dengue adjacency stays sparse**: dense it is
205 MB in float32 to encode 40,936 non-zeros (20,468 undirected edges), and the training loop uses a
sparse tensor throughout. One GPU means all GPU work is strictly serial, which is why the queue
scripts in §7 exist — two jobs sharing the card do not merely run slower, they change what the
timing-sensitive jobs measure.

Nothing requires this specific card. A CPU-only run works and is correct, but is impractical: the
full experiment set is ~60 GPU-hours and would be days on CPU. `run_overnight.py` refuses to start
without CUDA for exactly that reason.

## 4. Stage 1 — obtain the raw inputs

```bash
git clone <repository> && cd Ebola-Research
conda env create -f environment.yml

# 16 GADM 4.1 shapefiles, fetched and verified against a checksum manifest
python fetch_gadm.py

# the NYT COVID-19 series, fetched and verified against its pin
conda run -n ebola python loaders/covid_load.py --refresh

#   ...place the dengue extract, the Ebola compilation and the six influenza
#      matrices under "data/Final datasets/" — see §12 for URLs and checksums
```

If you have access to the DVC remote, `dvc pull` fetches L1 in one step instead.

**The shapefiles are fetched rather than redistributed.** GADM 4.1 is a frozen public release, so a
checksum manifest gives the same guarantee at negligible storage cost, and its licence forbids
commercial redistribution in any case. `fetch_gadm.py --verify` runs without network access and exits
non-zero on any mismatch.

## 5. Stage 2 — rebuild the datasets

One command rebuilds all six bundles from the raw sources:

```bash
conda run -n ebola python build_datasets.py
conda run -n ebola python build_datasets.py --check-deterministic   # build twice, compare arrays
```

Four steps, and the order is load-bearing:

1. **Verify.** Every raw input is hashed against a recorded checksum before anything is built — the
   dengue extract, the Ebola compilation, the six influenza matrices, the COVID-19 series, and all
   sixteen shapefiles. A drifted input changes every figure in the audit note while the bundles still
   pass their own schema checks, so a mismatch **halts** the build rather than warning.
2. **Construct.** Six bundles: dengue, influenza (japan / us-regions / us-states), Ebola, COVID-19.
3. **Gate.** The full leakage suite plus its negative controls. On any failure the build **writes
   nothing** — a dataset containing a leak, once on disk, is a dataset somebody will train on.
4. **Package.** Six `.npz` archives, plus `config.json` (every parameter that moves a number) and
   `env.txt` (a `pip freeze` of the environment that built them).

The two frozen Ebola support-set arms are a separate, deliberately manual step, because they are
pre-registered artifacts rather than build outputs:

```bash
conda run -n ebola python freeze_ebola_arms.py            # build, check, write, hash
conda run -n ebola python freeze_ebola_arms.py --verify    # rehash what is on disk
```

**Expected output.** `data/processed/` holds eight archives — `dengue.npz`, `influenza_japan.npz`,
`influenza_us-regions.npz`, `influenza_us-states.npz`, `covid_us-states.npz`, `ebola.npz`, and the
two frozen arms `ebola_L12.npz` and `ebola_L20.npz`. Their content digests are pinned in
[configs/ebola_arms.json](configs/ebola_arms.json) and §10.

**Why `.npz` and not a pickle.** A pickle couples the file to the class definitions and library
versions that wrote it — rename a field or upgrade a library and the file is unreadable — and
unpickling executes code, which makes it unsafe to hand a reviewer. The archives hold plain arrays
and a plain-text JSON metadata blob, readable by any tool that reads arrays.

## 6. Stage 3 — verify

Run these before trusting any result. Each is a script with no test framework; each exits non-zero on
failure.

| Command | Env | What it proves |
|---|---|---|
| `python -m tests.test_leakage` | `ebola` | **101 pass/fail gates across all six datasets** + 6 negative controls. Scaler fitting, no-future-leak, target/input separation, mask agreement, split ordering, rolling-origin family |
| `python -m tests.test_schema` | base | 34 unit tests of `to_schema.py` on synthetic fixtures mirroring the real raw layouts. No geospatial dependencies |
| `python -m tests.test_dengue_7_1` | `ebola` | Two properties of the actual OpenDengue file the loader assumes: counts are per-period, not cumulative; every weekly record falls in its true epidemiological week |
| `python -m tests.test_influenza_covariates` | `ebola` | The static covariates are joined to the right nodes, checked against geography known independently of GADM |
| `python -m tests.test_encoder_invariants` | `ebola-train` | The encoder's §8 invariants — C1 (transfer view only), C2 (no graph-sized parameter), C3 (identity before degree normalisation) — each with a negative control |
| `python bundles.py` | `ebola-train` | Six-bundle self-check across the loading interface |
| `python score.py` | `ebola-train` | Metric-layer self-check, including the country-macro construction |
| `python results_paths.py` | base | Artifact routing over 38 filename families |
| `python analysis.py --selfcheck` | `ebola-train` | The bootstrap engine and reads aggregation, on synthetic data |
| `python conformal.py --selfcheck` | `ebola-train` | The conformal and ACI logic, on synthetic data |

**Every gate ships with a negative control, and this is not a stylistic preference.** An earlier
version of the leakage suite recovered raw counts by inverting the normalised series with the very
scaler under test — circular — and it passed a deliberately leaked Ebola scaler with every gate
green. Each dataset therefore now carries its raw, unscaled incidence untouched by any scaler, every
scaler gate is evaluated against that, and `self_test()` plants real defects and requires the matching
gate to fail. A gate that cannot fail proves nothing.

The suite grew from 86 gates to 101 when COVID-19 moved inside `build_datasets.py`. While it was
built by a separate script it sat outside the gates entirely; folding it in brought it under the same
fifteen per-dataset checks every other panel passes.

## 7. Stage 4 — re-run the experiments

All training runs in `ebola-train`, from the repository root, as modules. Records land in
`results/<subdir>/` by filename, routed through `results_paths.rpath()` — change a location there and
both readers and writers follow.

### The experiment families

| Family | Command | Record files on disk | Documented runtime |
|---|---|---|---|
| **Single-disease ceiling** | `python -m train.loop --all` | `single/encoder__<ds>__seed<S>` — 25 (5 panels × 5 seeds) | dengue ~12.7 h; the three influenza panels ~35 min combined |
| **Naive floors** | (written by `--all` above) | `naive/naive__<ds>` — 7 | Minutes; deterministic, no seed |
| **Joint multi-disease** | `python -m train.joint --all` | `joint/encoder_joint__<tag>__<ds>__seed<S>` — 24 | not recorded |
| **LDO3 transfer** (3-way leave-one-disease-out) | `python -m train.lodo --all-ldo3` | `lodo/encoder_ldo3[_zeroshot]__…` — 50 | not recorded |
| **LDO3, full budget** (early stop disabled) | `python run_ldo3full.py` | `lodo/encoder_ldo3full[_zeroshot]__…` — 10 | ~3.5 h per fold |
| **Graph-controlled pair** (COVID ↔ influenza_us-states) | `python -m train.lodo --pair` | `lodo/encoder_pair[_zeroshot]__…` — 20 | ~6 h for the whole `run_overnight.py` queue |
| **Two-disease LDO** (superseded by LDO3, retained per client D1) | `python -m train.lodo --all-ldo` | `lodo/encoder_ldo[_zeroshot]__…` — 40 | not recorded |
| **Ebola case study** | `python -m train.ebola --all` | `ebola/encoder_ebola[_zeroshot]__<arm>__seed<S>` — 20 | not recorded · **scored once, see §10** |
| **Conformal calibration** | `python conformal.py --fit --lopo` then `--apply` | `misc/conformal_config.json`; applied to the archived quantiles | Minutes, CPU only — it reads archived quantiles and costs no GPU |
| **Baselines** | `python run_baselines.py` then `python score_baseline.py` | `baselines/<Model>__<ds>__h<H>__seed<S>` — 229 | not recorded |
| **Capacity probe** | `python -m diagnostics.capacity_probe --seeds 42 52 62 72 82` | `misc/capacity_probe*` | ~15 h (trunk 71 min + arm1 16 min + arm2 96 min per seed) |
| **Epi-informed ablation** | `python run_epi_night.py` | `ablation/single/encoder__…` | ~2.6 h for the four small panels; ~30 h if dengue is added |
| **Meta-learning ablation** (ANIL against its ERM control) | `python run_anil_night.py --folds influenza covid dengue` | `misc/anil_[ldo3<fold>_]affine_<arm>` — 16; `lodo/…anil-affine-…` — 80 records, 240 npz, 40 meta-trunks | ~12 h for the three LDO3 folds (dengue ~8 h, influenza ~2.7 h, covid ~1.3 h); the `dengue2flu` fold ~2.75 h |

**The runtimes above are the figures the runner scripts document, measured on the RTX 3060.** They
are not derived from the records, because **no record carries a wall-clock field** — a gap worth
closing, since it makes "how long does this take to reproduce" a question only the scripts' comments
can answer. Treat blank cells as unmeasured, not as fast.

Every long job is **resumable and keys its resume on the artifact, not on a flag**: a fold is done
when its checkpoint exists, because the checkpoint is the last write. Deriving the work list from the
evidence rather than from a resume marker keeps it correct however a previous attempt died — this is
what caught `influenza_us-regions` seed 52 sitting at 2 epochs of 80 after four sessions had each
skipped it.

### Smoke first

Every trainer has a `--smoke` path that runs the full code path on a small panel for a few epochs and
writes to `results/misc/`, where a throwaway cannot contaminate the record. Run it before committing
a card to a multi-hour job:

```bash
conda run -n ebola-train python -m train.loop  --smoke
conda run -n ebola-train python -m train.joint --smoke
conda run -n ebola-train python -m train.lodo  --smoke-ldo3
conda run -n ebola-train python -m train.ebola --dry-run
```

`train.anil` has no `--smoke`, because its cheap paths are finer grained. Use all three before a
meta-learning night, in this order: `--selfcheck` (logic only, seconds), `--preflight --fold <f>`
(prerequisites for every seed and every meta-train panel of that fold, seconds), and `--timing
--fold <f>` (prices one outer update against the measured trunk step, a few minutes). The night
runner calls all three itself and refuses to book anything if preflight fails on any requested fold.

### The queue scripts

One GPU means the schedule is part of the method. Four runners serialise multi-job nights, wait for
the card by polling `nvidia-smi`, and are safe to launch unattended:

| Script | What it queues |
|---|---|
| `run_overnight.py` | COVID ceiling + floors, then the transfer folds. Preflights for CUDA |
| `run_tonight.py` | Ebola (GPU) with the conformal fit detached beside it (CPU), then the ceilings |
| `run_ldo3full.py` | The two remaining full-budget LDO3 folds, back to back, then the comparison |
| `run_epi_night.py` | Waits out the LDO3 queue, then the epidemiology-informed ablation |
| `run_anil_night.py` | The meta-learning ablation. Fold-major, then seed-major with the **control before ANIL at each seed**, so a night that dies halfway leaves complete matched pairs rather than an unanalysable set of one-armed cells. Preflights every requested fold before booking any of them |

Each has `--selfcheck` (logic only, no GPU, seconds) and `--dry`/`--dry-run` (print the plan, run
nothing). The idle detector requires several *consecutive* polls below the memory threshold, because
a job between phases briefly frees its allocation and a single poll races it.

## 8. Stage 5 — regenerate the tables

These read L3 and write L4. None retrains, none rescores, none writes to `results/`.

| Command | Produces |
|---|---|
| `python results_matrix.py` | The consolidated results matrix: single vs joint vs LODO vs LDO, every regime on the full metric set, as one markdown document |
| `python ebola_report.py` | The Ebola case study read off disk, both arms, mean ± sd over 5 seeds, skill against each named floor |
| `python ebola_ci.py` | The pre-registered Ebola interval, recomputed on the statistic actually reported (node-averaged country-macro), resampling **districts and origins** |
| `python analysis.py --ci --reads` | Paired bootstrap-over-origins CIs (B = 10,000) and the gate/spatial-contribution reads |
| `python -m diagnostics.ldo3_report` | The LDO3 transfer tables |
| `python -m diagnostics.anil_report` | The meta-learning tables, four folds: ANIL against its own seed-matched control, and each arm against that fold's freeze-then-adapt reference. Verifies all 40 runs first and exits non-zero if any artifact is missing or disagrees with its filename |
| `python -m diagnostics.verify_anil_doc --mutate` | Reads the numbers back out of `ANIL_Results.md` and recomputes them from the artifacts **without importing the generator**, so a shared bug cannot verify itself. `--mutate` corrupts the document seven ways in memory and confirms each corruption is caught |
| `python -m diagnostics.paper_compare` | Our numbers against the published baseline claims |
| `python Reports/md_to_docx.py <file.md>` | The client-facing `.docx`, rendered from the markdown source |

**Four reporting rules are enforced in the readers, not left to the writer.** They exist because each
one was violated at least once before it was coded:

- **Every cell carries dispersion.** `mean ± sd` over seeds with the seed count; a 1-seed cell prints
  bare and is tagged `(1 seed)`, never dressed up as a mean.
- **Never average across datasets, and never across arms.** Dengue has 6,161 scored nodes and
  us-regions has 10; L12 and L20 are different pre-registered support sets, not two runs of one thing.
- **The comparison reference is stated in the table's own header.** "Improves by 12%" is meaningless
  without saying over what.
- **A delta whose paired-by-seed interval covers zero prints `within noise`,** not a sign. With 4–5
  seeds the t critical value is 2.78–3.18; using the normal quantile there would manufacture
  significance, so the readers carry a real t table.

`ebola_report.py` additionally refuses to print at all unless all 20 records agree on
`prereg_sha256`, `support_cells` and `support_cutoff` per arm — if they disagree, the run mixed
configurations and the table is not a single experiment.

## 9. Determinism: what is bit-reproducible and what is not

Stated precisely, because "reproducible" is doing different work in each of these three cases.

**The data build is bit-deterministic, and this is checked.** `build_datasets.py --check-deterministic`
builds twice and compares `X`, `A_geo`, `C`, `M` and `y` element-wise across all six bundles. The
`.npz` *files* are not byte-identical across rebuilds — a `.npz` is a zip and zip entries carry a
wall-clock timestamp — which is why `bundles.content_sha256()` exists: a canonical digest over the
arrays themselves, independent of zip framing. That digest is what makes "the frozen split has not
moved" a checkable claim, and it is the one recorded for the Ebola arms.

**Training is seeded but not bitwise-guaranteed across machines.** Every run sets
`torch.manual_seed(seed)` and `np.random.seed(seed)` before constructing the model. The project does
**not** set `torch.use_deterministic_algorithms(True)` or `cudnn.deterministic`, so a different GPU,
driver, or torch build may select different reduction orders and produce numerically different — not
merely differently-seeded — results.

On the machine of record, same-seed re-runs have been bit-identical in practice.
`diagnostics/ldo3full_check.py` pairs each full-budget LDO3 record with its truncated twin and hashes
the numeric fields: **8/8 records identical**, which is also the finding that settled the trunk
early-stop question. That is evidence of same-box stability at a matched seed, not a cross-platform
guarantee, and it should not be quoted as one.

**What carries the conclusions instead of bit equality.** Every headline is reported over **5 seeds
{42, 52, 62, 72, 82}** with dispersion, and every comparison is paired by seed so the shared
initialisation noise cancels. A conclusion that survives that treatment does not depend on any
individual run reproducing to the last bit — which is the property you actually want, since a reader
on different hardware will not get your bits regardless.

**Deliberate non-determinism: none.** The naive floors are computed analytically and carry no seed
(their records have `seed: null`). Bootstrap intervals seed their own resampling.

## 10. The Ebola one-way door

The Ebola case study is the headline deliverable and it is **scored exactly once**. This changes what
"reproduce" means for that one result, and the constraint is enforced in code rather than by
discipline.

**The protocol was frozen before any Ebola number existed.**
[Ebola_Prereg.md](progress/decisions/Ebola_Prereg.md) (frozen 2026-08-07, amendments A1–A7) fixes
every free parameter — the trunk definition, the adaptation epoch rule, the origin set, the metrics,
the floors, and the expected outcomes. §5.1 scores each arm once; §5a forbids adding anything
afterwards.

**Both support-set arms were built and hashed before either was scored.**

| Arm | Cutoff | Support columns | Content digest |
|---|---|---|---|
| `ebola_L12` (primary) | 2014-06-28 | 13 | `08d657dcc3856fbd3319e509d828a9697eefb91d9a7b1f2b6abbdd38454178fd` |
| `ebola_L20` (secondary) | 2014-08-23 | 21 | `e9b9ac0b44c2e3f71ba78a922a9125d1e0bc1b10e4e6547b3e8ce59855d28cc0` |

`freeze_ebola_arms.py --verify` rehashes what is on disk. `train/ebola.py` asserts the frozen hashes
before it will score anything, and stamps `prereg_sha256` into every record it writes.
`run_tonight.py` refuses to start the Ebola step if scored artifacts already sit in `results/ebola/`;
`--force-ebola` is the deliberate override and there is no accidental path to it.

**Ebola never enters selection.** All hyperparameters were chosen on the development diseases —
encoder settings on dev validation folds, adaptation settings by leave-one-development-disease-out —
then frozen. Ebola carries no validation split by design, appears in no early-stopping monitor (C8),
and enters `tests/test_encoder_invariants.py` only in structural readings that choose nothing.

**Therefore: reproducing the Ebola result means re-deriving the reported numbers from the archived
records, which `ebola_report.py` and `ebola_ci.py` do in seconds — not re-running `train/ebola.py`.**
A second scoring run would not be a replication; under the pre-registration it would be a protocol
violation that silently overwrote the record of the first.

## 12. Provenance

Every source is publicly available and pinned by checksum, verified at the start of every build. A
mismatch halts the build — no exceptions, no warnings.

| Source | Where to obtain it | Pinned by |
|---|---|---|
| OpenDengue, best-spatial extract V1.3 | Figshare, DOI [10.6084/m9.figshare.24259573](https://doi.org/10.6084/m9.figshare.24259573) | DOI + `0f59280e…9b9ababc` |
| Influenza benchmarks (6 files) | The ColaGNN repository; verified byte-identical to the EpiGNN mirror | `influenza/SHA256SUMS.txt` |
| Ebola compilation | [HDX](https://data.humdata.org/dataset/rowca-ebola-cases), resource `9b68ab69-e0b3-4ff5-b2d8-90bf446acd52` | `2d679a31…5f28f9f2` |
| COVID-19, US states | [NYT `covid-19-data`](https://github.com/nytimes/covid-19-data), `us-states.csv` | `0b202f6a…448dfc43` |
| GADM 4.1 (16 shapefiles) | Fetched by `fetch_gadm.py` | Checksum manifest |

The full hashes are in [build_datasets.py](build_datasets.py) `RAW_SHA256`, and every hash is of the
file **as published**, so a reader can hash their own download and compare directly.

**Three provenance facts worth knowing before you hash anything:**

- **The Ebola compilation is the only source with no version number,** so its checksum is its only
  version identifier. The recorded hash is the pristine published file. An earlier working copy had
  been opened and re-saved in a spreadsheet application — which rewrites the zip container without
  altering a single cell — and its contents and the dataset built from it were verified identical,
  but its hash was not the published one. A reviewer hashing their own download would have got a
  mismatch against a file that was in fact correct.
- **COVID-19 is fetched from a mutable path, which is exactly why it is pinned.** `us-states.csv`
  comes from the repository's `master` branch, a reference that can move by construction, even though
  the NYT repository was archived in March 2023. "Archived upstream" is a reason to expect stability,
  not a substitute for checking it. The digest is also stamped into the bundle's metadata as
  `raw_sha256`, so a released bundle traces to the exact bytes it came from.
- **Every data alteration is declared, reasoned and recorded in the bundle's own metadata** — the
  dengue alias maps and exclusions J1–J11, the Ebola drops, the COVID node exclusions. That register
  is the paper's data-methods section, and it lives in
  [data_audit.md](progress/planning/data_audit.md), not in anyone's head.

## Quick reference

```bash
# --- verify a checkout without running anything expensive -------------------
conda run -n ebola       python -m tests.test_leakage           # 101 gates + 6 controls
conda run -n ebola-train python -m tests.test_encoder_invariants
conda run -n ebola-train python bundles.py && python score.py
python results_paths.py && python -m tests.test_schema

# --- rebuild the datasets from raw ------------------------------------------
conda run -n ebola python build_datasets.py --check-deterministic
conda run -n ebola python freeze_ebola_arms.py --verify

# --- re-read the headline results (no GPU, seconds) -------------------------
conda run -n ebola-train python ebola_report.py
conda run -n ebola-train python ebola_ci.py
conda run -n ebola-train python results_matrix.py
conda run -n ebola-train python -m diagnostics.anil_report --verify-only
conda run -n ebola-train python -m diagnostics.verify_anil_doc --mutate
```
